Peeky Data: making CSV summaries harder to misread

Preserving identifiers, defining missing values, and testing the arithmetic behind a dashboard.

Yasaman Samiee · Updated September 17, 2026 · 3 min read

A CSV explorer can produce a polished table and still mislead its reader. A value such as 001 may be an identifier, an empty field may mean unknown, and a repeated row may represent a real repeated event. Peeky Data makes those assumptions visible instead of silently cleaning everything.

Preserve the uploaded representation

The parser keeps nonblank cell text, including leading zeros. Numeric analysis uses a separate conversion: every nonblank value must parse, and leading-zero integer strings stay text. A mixed column remains text. This is a conservative heuristic, not semantic type detection; an identifier without leading zeros can still look numeric.

Only blank and whitespace-only cells count as missing. Literal NA and N/A remain categories. A different dataset may need a different missing-value policy, which is why the report describes the rule rather than presenting it as universally correct.

Use the same values for every numeric view

The original implementation could detect numeric-looking text and later attempt to bin the unconverted column. The analysis now uses the same conversion helper for numeric statistics and distributions. Infinite values are counted explicitly and excluded from those calculations.

Another issue was a “Top 5” display showing the first five ordered intervals. The revised dashboard shows all ten intervals for numeric columns with more than ten distinct finite values. Other columns show the five most frequent values, with percentages calculated over all eligible values—not just the displayed five.

Make the assumptions testable

A fictional sample contains 15 rows, six columns, four missing cells, and one repeated row after its first occurrence. Those expected values provide a quick check that the dashboard and analysis agree.

The test suite also exercises broken quoting, inconsistent row lengths, duplicate headers, UTF-8 encoding, upload limits, numeric strings, all-infinite columns, undefined standard deviations, and JSON export. The published revision passed 18 tests locally and in GitHub Actions.

Export findings, not automatic decisions

The downloadable JSON report includes counts, column statistics, methodology, and suggested checks. It contains no individual records, though column names and aggregate statistics can still be sensitive. Uploads are processed on the app server, so the public demo asks visitors to use non-sensitive data.

Peeky Data does not decide whether to delete duplicates, fill missing values, or reject a dataset. The next useful extension would be explicit user-defined rules—such as allowed categories or a required unique ID—with failures reported separately from descriptive statistics.
