Boosting: correcting predictions and handling missing values

A small regression example, plus the difference between learned missing-value routes and imputation.

Yasaman Samiee · Updated September 17, 2026 · 3 min read

Boosting builds a prediction in stages. To make that concrete, start with three fictional regression targets: 10, 20, and 30. A constant prediction of 20 leaves residuals of −10, 0, and +10.

One update, not a complete model

For squared-error loss, a new tree can be fit to these residuals using the input features. Suppose its predictions are −8, −2, and +8. With a learning rate of 0.10, the updated predictions become 19.2, 19.8, and 20.8:

updated prediction = current prediction + learning rate × tree output

The sum of squared errors falls from 200 to 169.32: 84.64 + 0.04 + 84.64. This toy update illustrates the direction of improvement; it does not demonstrate generalization to unseen data.

Residual fitting is a special case

For other differentiable losses, gradient boosting follows negative loss gradients rather than ordinary target-minus-prediction residuals. XGBoost also uses second-order information in its tree objective and penalizes model complexity. Boosting rounds depend on earlier rounds; parallel split-finding does not remove that dependency. See the XGBoost model tutorial.

Missing values take a learned route

For tree models, XGBoost learns a default branch for missing values at a split. It does not need to fill every missing entry with an estimated numeric value. This distinction is documented in the XGBoost FAQ.

Imagine a feature measuring days since the last purchase. Missing might mean “new customer,” a failed data join, or a tracking outage. A tree may use that pattern successfully during training while failing when the meaning of missingness changes. Native support for missing values is not a substitute for understanding their source.

What I would compare before choosing a model

Start with a simple baseline and a split that matches the intended use. For forecasting future behavior, a random split can hide time-related leakage. Fit preprocessing only on training data and keep a final test set separate from early-stopping decisions.

Compare the baseline, a bagged tree model, and boosted trees on the same validation cases. Look at error by meaningful segment, training-versus-validation gaps, and behavior when key features are missing. Learning rate, tree depth, and the number of boosting rounds interact; a stronger fit to training data is not the goal by itself.

Bagging combines models trained on resampled data and is often used to reduce variance. Boosting adds models sequentially to improve an objective. Both can overfit, and neither removes the need for a defensible evaluation design.
