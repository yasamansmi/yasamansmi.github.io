Transformers: following a token through one block

Embeddings, attention, and feed-forward layers without the unrelated detours.

Yasaman Samiee · Updated September 17, 2026 · 2 min read

A transformer builds contextual representations using attention and feed-forward layers. Its defining distinction from a recurrent architecture is not that it learns from examples—both do—but how it exchanges information between positions.

From token IDs to contextual vectors

Token IDs index an embedding table. Position information lets the model distinguish sequences with different order. Within an attention head, learned projections form queries, keys, and values. Query-key scores, scaled and normalized with softmax, weight the values.

Multiple heads allow different learned projections. A feed-forward network then transforms each position’s representation. Residual connections and normalization support the stack; their ordering varies across architectures.

The mask changes the task

In a causal decoder, a position cannot attend to future tokens. During training, many positions can be processed together under that mask. Autoregressive generation still produces tokens sequentially. An encoder can use bidirectional attention; an encoder-decoder model can additionally attend to encoder outputs.

What reaches the output

For language generation, the final representation is projected to vocabulary logits. Softmax converts those logits to probabilities. Embedding dimensions are model-specific, and individual coordinates generally do not have a simple named interpretation.

A larger context window allows more tokens as input. It does not guarantee the model will correctly use every fact inside that window.

Architecture reference: Attention Is All You Need. This note describes the main components, not every later transformer variant.
