BFS and DFS: choose by the search you need

Shortest paths in unweighted graphs, traversal order, and memory on different tree shapes.

Yasaman Samiee · Updated September 17, 2026 · 2 min read

Breadth-first search explores vertices by distance from a starting point. Depth-first search follows a branch before backtracking. Both need a visited set on general graphs to avoid repeatedly traversing cycles.

A minimal graph BFS

from collections import deque

def distances(graph, start):
    distance = {start: 0}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        for neighbor in graph.get(node, []):
            if neighbor not in distance:
                distance[neighbor] = distance[node] + 1
                queue.append(neighbor)
    return distance

Marking a vertex when it enters the queue prevents duplicate enqueues. For A → B, A → C, B → D, C → D, the distances from A are 0, 1, 1, and 2. The same approach works with cycles because previously discovered vertices are skipped.

Distance depends on the edge model

BFS finds shortest paths by number of edges in an unweighted graph. It does not generally minimize unequal edge costs. DFS is useful for exploration and as a component of algorithms such as cycle detection, but its first discovered path need not be shortest.

Time and space

With adjacency lists, both traversals take O(V + E) time over the reachable graph. A visited set may use O(V) memory. On a tree without a visited set, BFS frontier memory depends on width, while recursive DFS stack memory depends on height. A chain has constant-width BFS frontier and an O(V) DFS stack; a balanced binary tree reverses much of that memory tradeoff.

Reference implementation and discussion: Princeton Algorithms: undirected graphs.
